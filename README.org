#+TITLE: org-chronicle

=org-chronicle= is an Emacs package for capturing, maintaining, and
viewing a timeline of events for a historical-fiction project.  Events
are Org headings with property drawers (truth flag, date, participants,
location, sources) gathered from all =*.org= files under a project root
directory; people, places, and groups can be promoted to entity headings
that carry aliases, existence spans, and kinship — then the package's
swimlane view and anachronism lint cross-reference them automatically.

* Installation

Clone the repository and add its directory to your =load-path=, then
load the package:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/org-chronicle")
(require 'org-chronicle)
#+end_src

Emacs 27.1+ and Org 9.4+ are required.

** With use-package

Since the package is not yet on a package archive, install it straight
from the repository URL with =package-vc-install= (built in since Emacs
29.1), then let =use-package= configure it.  This is the recommended
form: it behaves identically on Emacs 29 and 30.  The public commands
are autoloaded, so =:commands= keeps startup cheap, and =:custom= sets
the data-file locations:

#+begin_src emacs-lisp
(unless (package-installed-p 'org-chronicle)
  (package-vc-install "https://github.com/andapony/org-chronicle"))

(use-package org-chronicle
  :ensure nil
  :commands (org-chronicle-add-event
             org-chronicle-add-topic
             org-chronicle-timeline
             org-chronicle-lint)
  :custom
  (org-chronicle-root "~/org/chronicle/")
  (org-chronicle-lane-column-width 24))
#+end_src

=:ensure nil= keeps =use-package= from trying to fetch the package from
a package archive when =use-package-always-ensure= is set;
=package-vc-install= has already put it on the =load-path=.  Given a
bare URL, =package-vc-install= tracks the default branch, so
=package-vc-upgrade= fast-forwards.

On *Emacs 30 or newer*, =use-package= understands the =:vc= keyword, so
you can drop the =package-vc-install= line and fold the install into the
declaration instead.  Keep =:rev :newest=: without it =:vc= checks out
the latest release as a detached HEAD, and =package-vc-upgrade= then
silently does nothing — its =git pull= has no branch to merge into.
(Note: =:vc= is *not* recognized by the =use-package= bundled with Emacs
29 — it raises "Unrecognized keyword: :vc" — so use the
=package-vc-install= form above there.)

#+begin_src emacs-lisp
(use-package org-chronicle
  :vc (:url "https://github.com/andapony/org-chronicle" :rev :newest)
  :commands (org-chronicle-add-event org-chronicle-timeline))
#+end_src

Or, if you prefer a manual clone, add =:load-path "/path/to/org-chronicle"=
to the =use-package= form (keeping =:ensure nil=) instead of installing
from the URL.

To explore the package before wiring up your own files, copy the
bundled =examples/= directory somewhere and set =org-chronicle-root= to
that copy, then run =M-x org-chronicle-timeline=.

* Configuration

All paths and display options are customizable via =M-x customize-group
RET org-chronicle RET=.  The key variables are:

#+begin_quote
*Breaking change:* =org-chronicle-entities-files= has been removed.
Reading is now done by recursive directory scan of =org-chronicle-root=;
=org-chronicle-timeline-file= is now a write target only.
#+end_quote

** Read sources

- =org-chronicle-root= :: Root directory scanned recursively for
  =*.org= files.  Every file found contributes both events and entities
  unless excluded (default =nil=, which you must set before use).
- =org-chronicle-exclude= :: List of regular expressions.  A candidate
  file whose path relative to the root — with a leading =/= prepended —
  matches any regexp is skipped entirely.  Example: =("/drafts/")=
  excludes every file under a =drafts/= subdirectory.

  Both =org-chronicle-root= and =org-chronicle-exclude= are declared
  =safe-local-variable=, so you can set them per-project in
  =.dir-locals.el=:

  #+begin_src emacs-lisp
  ((nil . ((org-chronicle-root . "~/writing/novel/")
           (org-chronicle-exclude . ("/drafts/")))))
  #+end_src

- =#+CHRONICLE: ignore= :: Place this keyword anywhere in an Org file
  to make that single file contribute no events or entities, without
  adding it to =org-chronicle-exclude=.

** Write targets

These variables control where new headings are filed.  Each defaults to
=nil=, which resolves to the named file directly under
=org-chronicle-root= (e.g. =timeline.org=, =people.org=).  Set them
only when you want a non-default location.

- =org-chronicle-timeline-file= :: File where new events are appended
  (default: =timeline.org= under the root).
- =org-chronicle-people-file= :: File where new person and group
  entities are filed (default: =people.org= under the root).
- =org-chronicle-places-file= :: File where new place entities are
  filed (default: =places.org= under the root).
- =org-chronicle-topics-file= :: File where new topic entities are
  filed (default: =topics.org= under the root).

** Display

- =org-chronicle-topic-glyphs= :: Alist mapping topic names to glyph
  strings shown in that topic's timeline column (default =nil=).
- =org-chronicle-topic-faces= :: Alist mapping topic names to faces
  applied in that topic's timeline column (default =nil=).
- =org-chronicle-lane-column-width= :: Width in columns of each lane in
  the timeline view (default =22=).

* Capturing events

Use =M-x org-chronicle-add-event= to interactively capture a new event
into the timeline file.  It prompts for title, date, truth level
(=historical= / =fictionalized= / =fictional=), participants, location,
and topics, then appends the heading and runs =org-chronicle-normalize=.

For integration with =org-capture=, use =org-chronicle-capture= as the
template body:

#+begin_src emacs-lisp
(add-to-list 'org-capture-templates
  '("ce" "Chronicle event" entry
    (file org-chronicle-timeline-file)
    "%(org-chronicle-capture)" :empty-lines 1))
#+end_src

To edit an event that already exists, put point on its heading and run
=M-x org-chronicle-add-to-event=.  It asks for a domain (person, place,
or topic) and then a value, completing against that domain's known
entities.  People and topics are appended to their multi-value property
(duplicates skipped); a location replaces the existing one after
confirmation.  The event is re-normalized afterward.

* Life events

Births, deaths, marriages, and name changes are first-class timeline
events.  Capture them with =M-x org-chronicle-add-life-event=, which asks
the kind and adapts its prompts (one subject for birth/death/name-change,
two for marriage; births also prompt for parents).  A person's lifespan,
birthplace/deathplace, and spouse are derived from these events, falling
back to the =:BORN:= / =:DIED:= / =:BIRTHPLACE:= / =:DEATHPLACE:= / =:SPOUSE:=
properties when no event exists.  =org-chronicle-add-person= offers to
create a birth event after filing the person.

* Entities

People, places, and groups can be promoted to *entity headings* that
carry aliases, existence spans, and kinship — the anchors the swimlane
view and anachronism lint cross-reference.  Create them directly:

- =M-x org-chronicle-add-person= :: file a person into
  =org-chronicle-people-file=; prompts for aliases, birth, death, and
  group membership, and offers to capture a birth life event.
- =M-x org-chronicle-add-place= :: file a place into
  =org-chronicle-places-file=; prompts for an optional build/raze span.
- =M-x org-chronicle-add-group= :: file a group into
  =org-chronicle-people-file=.

Each refuses to create a duplicate of an existing entity without
confirmation.  (Topics are entities too; see [[*Topics][Topics]].
Real historical subjects can instead be imported from an external
source; see [[*Importing from external sources][Importing from external
sources]].)

To turn a name already written in your prose into a person entity, put
point on it and run =M-x org-chronicle-promote=: it seeds the new
entity's =ALIASES= with the literal text you promoted and prompts for the
canonical name.

=M-x org-chronicle-lint= checks the whole timeline for anachronisms,
reporting every event that falls outside a participant's or place's
existence span.  (For scene-level continuity of your prose, see
[[*Writing: scenes & continuity][Writing: scenes & continuity]].)

* Topics

A topic is a thematic thread that cuts across events — crime, shipping,
census, disease, or any other recurring theme in your project.  Events
carry topics in a =:TOPICS:= property (semicolon-separated, alias-resolved
like =:PEOPLE:=).

Create a topic entity with =M-x org-chronicle-add-topic=, which prompts
for a name, optional aliases, and an optional description, then files the
heading into =org-chronicle-topics-file= (default =topics.org= under the
root).  The file is picked up automatically on the next scan of
=org-chronicle-root=.

In the timeline view, each topic becomes its own swimlane column.  Pass
topic names interactively via the "Topics (lanes): " prompt, or set the
=:topics= parameter in a dynamic block:

#+begin_example
#+BEGIN: chronicle :topics ("crime" "shipping") :from "1850" :until "1855"
#+END:
#+end_example

Per-topic glyphs and faces are configurable via
=org-chronicle-topic-glyphs= (alist of topic-name to glyph string) and
=org-chronicle-topic-faces= (alist of topic-name to face).  A glyph or
face defined for a topic applies only within that topic's own column.

* Timeline view

=M-x org-chronicle-timeline= prompts for lane names (people or places),
a truth subset, and expand/collapse mode, then opens a read-only
swimlane buffer.  Press =RET= on a cell to jump to the source heading,
=g= to refresh, and =q= to quit.

** Building the view interactively

You do not have to name every lane up front.  The view is an editable
query: start from a small set of lanes and grow or trim the columns in
place.

- =+= — *expand the event(s) at point*: offers the people, places, and
  topics that the event references and adds the ones you pick as new
  lanes.  With point on a specific event cell it uses that event; placed
  elsewhere on a date row it falls back to every event on that date; on
  the header or a blank line it reports that there is no event at point.
- =a= — *add an arbitrary lane*: choose from all known people, places,
  and topics, regardless of what is on screen.
- =-= — *remove a lane*: drops the lane under point (on its header or a
  cell), or, when point is not on a lane, prompts for the lanes to
  remove by name.
- =<= / =>= — *move the lane at point* one column left or right.  Point
  follows the lane, so repeated presses slide it across the row.  The
  order is saved by =D= and by bookmarking.

Both add commands offer one combined, domain-tagged completion list
(e.g. =Ada Lovelace [person]=, =London [place]=) and exclude lanes
already shown; nothing is pre-selected.

** Saving a view

A view you have built can be saved two ways, both serializing the same
query:

- =C-x r m= bookmarks the current view (standard Emacs bookmarks);
  jumping to the bookmark re-runs the timeline and restores it.
- =D= copies the current view as a =chronicle= dynamic block to the
  kill-ring, ready to yank into an Org document.

The same view is available as an Org dynamic block:

#+begin_example
#+BEGIN: chronicle :people ("Grant" "Lincoln") :from "1862" :until "1865" :mode :collapse
#+END:
#+end_example

Parameters: =:people=, =:locations=, and =:topics= (lists of lane names),
=:truth= (list of allowed truth strings), =:from= and =:until= (date
strings), =:mode= (=:collapse= or =:expand= for groups/parent places).

* Sources

=M-x org-chronicle-add-source= appends a source to the =SOURCES=
property of the event at point.  When =org-reading-list= is loaded, it
completes over your reading list and files the citation as an =orl:=
link with an optional locator, e.g.

#+begin_example
:SOURCES: [[orl:foote1963][Foote, The Civil War (1963)]] p.412
#+end_example

Following the link jumps to the book's entry.  Without =org-reading-list=
loaded — or on a blank pick — it falls back to a free-text citation, so
there is no hard dependency.  Only reading-list entries that carry a
=:CUSTOM_ID:= are offered; run =M-x org-reading-list-ensure-citekeys=
there once to make any legacy entries citable.

=M-x org-chronicle-book-citations= is the reverse lookup: it lists every
chronicle event whose =SOURCES= cite a given book.  Run on a reading-list
entry it uses that entry's citekey; elsewhere it prompts.  The results
open in a read-only buffer — =RET= jumps to a citing event, =q= quits.

* Importing from external sources

The optional =org-chronicle-sources= module fetches vitals, kinship
relations, existence spans, and curated events for real historical
subjects from a linked-data source and proposes them as opt-in changes to
your chronicle.  Two sources are built in — *Wikidata* (the default) and
*FactGrid* — chosen with =org-chronicle-default-source= (=wikidata= or
=factgrid=).  Load the module with:

#+begin_src emacs-lisp
(require 'org-chronicle-sources)
#+end_src

The public commands are autoloaded, so an installed package needs no
explicit =require=.  Every command needs network access to the chosen
source: its MediaWiki API for name search and its SPARQL endpoint for the
record fetch.

Imported headings are filed into dedicated files, each defaulting to a
path under =org-chronicle-root=:

- =org-chronicle-sources-events-file= :: imported events (default
  =imported/events.org=).
- =org-chronicle-sources-people-file= / =org-chronicle-sources-places-file=
  / =org-chronicle-sources-groups-file= :: bulk-imported person, place,
  and group entities.
- =org-chronicle-sources-bulk-limit= :: cap on the number of rows a bulk
  query returns (default =500=).

All imported files are created on demand and scanned like any other
chronicle file, so imported items appear interleaved with your authored
ones on the timeline.

** Reviewing proposed changes

Every import opens an =*Import Review*= buffer listing each proposed
change with its current selection state:

- =TAB= toggles a row selected / deselected.
- =c= clears the selection (deselects every row).
- =RET= applies the selected set and closes the buffer.
- =q= cancels without writing anything.

New vitals and life-event changes are selected by default; curated
position events are deselected by default.  Changes that already match
your copy, or that conflict with a value you have, are shown but left
unselected, so a re-import never overwrites anything without an explicit
choice.

** =org-chronicle-import= — one subject

=M-x org-chronicle-import= imports a single subject's data into the
chronicle, resolving or creating the entity at point.

*Resolution.* When the heading already carries the source's key property
(e.g. =WIKIDATA=) the stored id is reused immediately.  Otherwise the
command opens a prompt seeded with the heading name; pasting a bare id
(e.g. =Q7259=) or a full item URL short-circuits the network search, and a
plain name queries the source's search API and presents candidates for
selection with =completing-read=.

*Resolve-or-create.* The command can be invoked in three situations: (1)
point on a =KIND: person= entity heading — the existing entity is enriched
in place; (2) point on a =PARENTS= or =SPOUSE= property line — the first
name in that value seeds the search, a minimal person entity is written to
the people file without interactive prompts, and then it is enriched; (3)
point on any other heading — a minimal person entity is written to the
people file and enriched.  In all cases the entity is saved to its file
before returning.

*Fetch and review.* The resolved id runs SPARQL queries (vitals, spouses,
positions held) against the source endpoint.  The results are mapped to a
proposed change set covering entity properties (=BORN=, =DIED=,
=BIRTHPLACE=, =DEATHPLACE=, =PARENTS=, =SPOUSE=, =ALIASES=, and the
source-key property such as =WIKIDATA=) and timeline events (birth, death,
marriages, and curated position events), presented in the review buffer
described above.

*What gets written.* Applied entity changes are written as properties on
the heading (in place, so a re-import refreshes rather than duplicates).
Applied event changes are written to =org-chronicle-sources-events-file=.
Each imported event carries an =IMPORT-KEY= identifying the real-world
event independently of its source, so re-running an import updates the
keyed heading in place instead of appending a duplicate.  Every imported
property and event is marked =TRUTH: historical= and records a =SOURCES=
link to the source item URL; the source id is stored in its key property
(e.g. =WIKIDATA=) for future reconciliation.

** =org-chronicle-reconcile= — pull upstream drift

=M-x org-chronicle-reconcile= re-queries the source item linked from the
heading and presents only the changes that have drifted from your local
copy.  Drift covers both entity properties and imported events: a property
or event that is missing locally (new), or whose value has changed
upstream (conflict) — for an event, a changed date or place — is shown as
an opt-in pull, while items that already match are suppressed.  Imported
events are matched by their =IMPORT-KEY=, so a pulled conflict updates the
existing event heading in place rather than duplicating it.  The same
review buffer is used; each row shows whether the change is new or a
conflict, and nothing is overwritten without explicit selection.  When
several source keys are present on the heading it prompts for which to
reconcile.  (Events that have been *removed* upstream are not yet
detected.)

** Bulk import

Three commands import many related items at once.  Each prompts for the
source, a scope, and a from/until year range, then opens the same
=*Import Review*= buffer:

- =M-x org-chronicle-import-events= :: events located at a place within
  the year range.
- =M-x org-chronicle-import-people= :: people connected to an anchor
  entity by a relation — lived or worked in a place, born in a place,
  member of a group, or participant in an event — optionally filtered by
  occupation.
- =M-x org-chronicle-import-foundings= :: places and groups founded or
  built within a place and year range, together with their founding
  events.

=M-x org-chronicle-add-entity-from-source= adds a single named entity of a
chosen kind (person, place, or group) from the source; interactively the
name and kind default to the entity heading at point, the active region,
or a prompt.

** Places and groups

Import and reconcile work for =place= and =group= entities, not just people.  On a
heading carrying =KIND: place= or =KIND: group=, the commands fill the entity's
existence span — =BUILT= / =RAZED= for places, =FOUNDED= / =DISBANDED= for groups —
from the source's inception property (Wikidata's =P571=) and dissolved property
(=P576=), together with =ALIASES=.  =org-chronicle-add-entity-from-source= prompts for
the kind before filing the heading.  These spans are what give the anachronism lint real
bounds to check fiction against: a scene set before a building was built or after a
group disbanded is flagged the same way as a scene that misplaces a person's lifespan.

** Date coverage

The integration targets mostly-modern, precisely-dated subjects.  Dates
coarser than a year (decade or century Wikidata precision), BCE dates, and
dates before the year 1000 CE are not representable by the
=org-chronicle= date model and are dropped rather than approximated.
Affected fields are silently omitted from the proposed change set.

When Wikidata holds competing birth or death statements — for example
because the Old Style / New Style calendar ambiguity gives a subject two
equally-cited dates — the importer selects a single value by statement
rank (preferred over normal; deprecated dropped) and then by precision,
choosing the most precise representable date among the surviving
candidates.  Rejected values appear in the review buffer as an informational
note on the same row, e.g.:

#+begin_example
BORN         <1643-01-04>  (Wikidata also lists: 1642)
#+end_example

Nothing is lost silently: the alternates are visible at review time so you
can see what was set aside.  All dates follow the proleptic Gregorian
calendar as stored by Wikidata.

** Testing

The module ships an offline test suite that runs with =make test= (or =make
all=, which additionally byte-compiles and runs checkdoc).  An opt-in live
suite can be run with =make test-live=; it exercises the HTTP fetch layer and
performs an end-to-end import against the real Wikidata SPARQL endpoint.  The
live suite is never invoked by =make all=, and individual tests skip rather
than fail when Wikidata is unreachable.

* Writing: scenes & continuity

Tie creative prose to the timeline and check it for continuity with the
historical record.  A *scene* is any heading carrying =:EVENT:=,
=:AFTER:= / =:BEFORE:=, a fictional own =:DATE:=, or an inline =chronicle:=
link.  Because a scene is just a property on a heading you already have, this
composes with org-novelist and binder layouts and stays invisible in the
exported manuscript.  (fountain-mode files are not Org, so scene markup does
not apply to them.)

#+begin_src org
,*** The siege begins
    :PROPERTIES:
    :EVENT: [[id:vicksburg-1863]]
    :END:
    Grant's guns opened at dawn.  [[chronicle:eliza][Mrs. Grant]] watched.
#+end_src

A scene may instead *define a fictional event* by carrying its own =:DATE:=
(and =:TRUTH: fictional=), optionally constrained relative to other events:

#+begin_src org
,*** A wager in the officers' tent
    :PROPERTIES:
    :DATE:   <1863-06-20>
    :TRUTH:  fictional
    :AFTER:  [[id:vicksburg-1863]]
    :BEFORE: [[id:appomattox-1865]]
    :END:
#+end_src

- =M-x org-chronicle-insert-reference= inserts an inline =chronicle:= link.
- =M-x org-chronicle-set-event= / =org-chronicle-add-constraint= set the
  =:EVENT:= / =:AFTER:= / =:BEFORE:= properties with completion.
- =M-x org-chronicle-lint-scenes= reports each scene's continuity findings and
  its *feasible window* — the range in which every reference and constraint is
  satisfied.  Floating (undated) scenes are surfaced with their window; an
  empty window means the references cannot co-exist at any date.
- =M-x org-chronicle-set-scene-date= (or =s= on a finding in the lint buffer)
  sets the scene's =:DATE:= to a value chosen from that window.

Constraints are evaluated against referents' *current* dates — there is no
propagation.  Pin scenes bounded by historical events first, then re-run the
lint as you place the rest.
