#+TITLE: org-chronicle

=org-chronicle= is an Emacs package for capturing, maintaining, and
viewing a timeline of events for a historical-fiction project.  Events
are Org headings with property drawers (truth flag, date, participants,
location, sources) gathered from all =*.org= files under a project root
directory; people, places, and groups can be promoted to entity headings
that carry aliases, existence spans, and kinship — then the package's
swimlane view and anachronism lint cross-reference them automatically.

* Installation

Clone the repository and add its directory to your =load-path=, then
load the package:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/org-chronicle")
(require 'org-chronicle)
#+end_src

Emacs 27.1+ and Org 9.4+ are required.

** With use-package

Since the package is not yet on a package archive, install it straight
from the repository URL with =package-vc-install= (built in since Emacs
29), then let =use-package= configure it.  The public commands are
autoloaded, so =:commands= keeps startup cheap, and =:custom= sets the
data-file locations:

#+begin_src emacs-lisp
(unless (package-installed-p 'org-chronicle)
  (package-vc-install "https://github.com/andapony/org-chronicle"))

(use-package org-chronicle
  :commands (org-chronicle-add-event
             org-chronicle-add-topic
             org-chronicle-timeline
             org-chronicle-lint)
  :custom
  (org-chronicle-root "~/org/chronicle/")
  (org-chronicle-lane-column-width 24))
#+end_src

On *Emacs 30 or newer*, =use-package= understands the =:vc= keyword, so
you can drop the =package-vc-install= line and fold the install into the
declaration instead.  (Note: =:vc= is *not* recognized by the
=use-package= bundled with Emacs 29 — it raises "Unrecognized keyword:
:vc" — so use the =package-vc-install= form above there.)

#+begin_src emacs-lisp
(use-package org-chronicle
  :vc (:url "https://github.com/andapony/org-chronicle" :rev :newest)
  :commands (org-chronicle-add-event org-chronicle-timeline))
#+end_src

Or, if you prefer a manual clone, add =:load-path "/path/to/org-chronicle"=
to the =use-package= form instead of installing from the URL.

To explore the package before wiring up your own files, copy the
bundled =examples/= directory somewhere and set =org-chronicle-root= to
that copy, then run =M-x org-chronicle-timeline=.

* Configuration

All paths and display options are customizable via =M-x customize-group
RET org-chronicle RET=.  The key variables are:

#+begin_quote
*Breaking change:* =org-chronicle-entities-files= has been removed.
Reading is now done by recursive directory scan of =org-chronicle-root=;
=org-chronicle-timeline-file= is now a write target only.
#+end_quote

** Read sources

- =org-chronicle-root= :: Root directory scanned recursively for
  =*.org= files.  Every file found contributes both events and entities
  unless excluded (default =nil=, which you must set before use).
- =org-chronicle-exclude= :: List of regular expressions.  A candidate
  file whose path relative to the root — with a leading =/= prepended —
  matches any regexp is skipped entirely.  Example: =("/drafts/")=
  excludes every file under a =drafts/= subdirectory.

  Both =org-chronicle-root= and =org-chronicle-exclude= are declared
  =safe-local-variable=, so you can set them per-project in
  =.dir-locals.el=:

  #+begin_src emacs-lisp
  ((nil . ((org-chronicle-root . "~/writing/novel/")
           (org-chronicle-exclude . ("/drafts/")))))
  #+end_src

- =#+CHRONICLE: ignore= :: Place this keyword anywhere in an Org file
  to make that single file contribute no events or entities, without
  adding it to =org-chronicle-exclude=.

** Write targets

These variables control where new headings are filed.  Each defaults to
=nil=, which resolves to the named file directly under
=org-chronicle-root= (e.g. =timeline.org=, =people.org=).  Set them
only when you want a non-default location.

- =org-chronicle-timeline-file= :: File where new events are appended
  (default: =timeline.org= under the root).
- =org-chronicle-people-file= :: File where new person and group
  entities are filed (default: =people.org= under the root).
- =org-chronicle-places-file= :: File where new place entities are
  filed (default: =places.org= under the root).
- =org-chronicle-topics-file= :: File where new topic entities are
  filed (default: =topics.org= under the root).

** Display

- =org-chronicle-topic-glyphs= :: Alist mapping topic names to glyph
  strings shown in that topic's timeline column (default =nil=).
- =org-chronicle-topic-faces= :: Alist mapping topic names to faces
  applied in that topic's timeline column (default =nil=).
- =org-chronicle-lane-column-width= :: Width in columns of each lane in
  the timeline view (default =22=).

* Capturing events

Use =M-x org-chronicle-add-event= to interactively capture a new event
into the timeline file.  It prompts for title, date, truth level
(=historical= / =fictionalized= / =fictional=), participants, location,
and topics, then appends the heading and runs =org-chronicle-normalize=.

For integration with =org-capture=, use =org-chronicle-capture= as the
template body:

#+begin_src emacs-lisp
(add-to-list 'org-capture-templates
  '("ce" "Chronicle event" entry
    (file org-chronicle-timeline-file)
    "%(org-chronicle-capture)" :empty-lines 1))
#+end_src

* Life events

Births, deaths, marriages, and name changes are first-class timeline
events.  Capture them with =M-x org-chronicle-add-life-event=, which asks
the kind and adapts its prompts (one subject for birth/death/name-change,
two for marriage; births also prompt for parents).  A person's lifespan,
birthplace/deathplace, and spouse are derived from these events, falling
back to the =:BORN:= / =:DIED:= / =:BIRTHPLACE:= / =:DEATHPLACE:= / =:SPOUSE:=
properties when no event exists.  =org-chronicle-add-person= offers to
create a birth event after filing the person.

* Topics

A topic is a thematic thread that cuts across events — crime, shipping,
census, disease, or any other recurring theme in your project.  Events
carry topics in a =:TOPICS:= property (semicolon-separated, alias-resolved
like =:PEOPLE:=).

Create a topic entity with =M-x org-chronicle-add-topic=, which prompts
for a name, optional aliases, and an optional description, then files the
heading into =org-chronicle-topics-file= (default =topics.org= under the
root).  The file is picked up automatically on the next scan of
=org-chronicle-root=.

In the timeline view, each topic becomes its own swimlane column.  Pass
topic names interactively via the "Topics (lanes): " prompt, or set the
=:topics= parameter in a dynamic block:

#+begin_example
#+BEGIN: chronicle :topics ("crime" "shipping") :from "1850" :until "1855"
#+END:
#+end_example

Per-topic glyphs and faces are configurable via
=org-chronicle-topic-glyphs= (alist of topic-name to glyph string) and
=org-chronicle-topic-faces= (alist of topic-name to face).  A glyph or
face defined for a topic applies only within that topic's own column.

* Timeline view

=M-x org-chronicle-timeline= prompts for lane names (people or places),
a truth subset, and expand/collapse mode, then opens a read-only
swimlane buffer.  Press =RET= on a cell to jump to the source heading,
=g= to refresh, and =q= to quit.

The same view is available as an Org dynamic block:

#+begin_example
#+BEGIN: chronicle :people ("Grant" "Lincoln") :from "1862" :until "1865" :mode :collapse
#+END:
#+end_example

Parameters: =:people=, =:locations=, and =:topics= (lists of lane names),
=:truth= (list of allowed truth strings), =:from= and =:until= (date
strings), =:mode= (=:collapse= or =:expand= for groups/parent places).

* Sources

=M-x org-chronicle-add-source= appends a source to the =SOURCES=
property of the event at point.  When =org-reading-list= is loaded,
it offers completion over that reading list and builds an =id:= link
with an optional locator (e.g. page number); otherwise it falls back
to free-text input.  There is no hard dependency on =org-reading-list=.

* Wikidata integration

The optional =org-chronicle-wikidata= module fetches vitals, kinship
relations, and curated life events for real historical figures from
Wikidata and proposes them as opt-in changes to your chronicle.  Load it
with:

#+begin_src emacs-lisp
(require 'org-chronicle-wikidata)
#+end_src

Both commands require network access to Wikidata: =wbsearchentities= (the
MediaWiki API) for name search and the Wikidata SPARQL Query Service for
record fetch.

** =org-chronicle-wikidata-import=

=M-x org-chronicle-wikidata-import= imports a person's Wikidata data into
the chronicle.

*Resolution.* When the heading already has a =WIKIDATA= property the
stored QID is reused immediately.  Otherwise the command opens a prompt
seeded with the heading name; pasting a bare QID (e.g. =Q7259=) or a full
Wikidata URL short-circuits the network search.  Entering a plain name
queries =wbsearchentities= and presents candidates for selection with
=completing-read=.  A special affordance exists for kinship properties:
invoking the command while point is on a =PARENTS= or =SPOUSE= property
line seeds the search with the first name in that value and then, if the
person does not already exist as an entity, creates it via
=org-chronicle-add-person= before enriching it.

*Fetch and review.* The resolved QID is used to run three SPARQL queries
(vitals, spouses, positions held) against the Wikidata Query Service.
The results are mapped to a proposed change set covering entity properties
(=BORN=, =DIED=, =BIRTHPLACE=, =DEATHPLACE=, =PARENTS=, =SPOUSE=,
=ALIASES=, =WIKIDATA=) and timeline events (birth, death, marriages, and
curated position events).  A =*Wikidata Import*= buffer opens listing
each proposed change with its current selection state:

- =TAB= toggles a row selected / deselected.
- =RET= applies the selected set and closes the buffer.
- =q= cancels without writing anything.

Vitals and life-event changes are selected by default; curated position
events are deselected by default.

*What gets written.* Applied entity changes are written as properties on
the heading.  Applied event changes are appended to the chronicle timeline
file.  Every imported property is marked =TRUTH: historical= and a
=SOURCES= link pointing to the Wikidata item URL is recorded on the
heading.  The QID is also stored in a =WIKIDATA= property for future
reconciliation.

** =org-chronicle-wikidata-reconcile=

=M-x org-chronicle-wikidata-reconcile= re-queries the Wikidata item
stored in the heading's =WIKIDATA= property and presents only the changes
that have drifted from your local copy: fields missing locally or where
the upstream value differs from what you have.  Fields that already match
are suppressed.  The same review buffer is used; each row shows whether the
change is new (absent locally) or a conflict (upstream value differs).
Nothing is overwritten without explicit selection.

The command requires a =WIKIDATA= property on the heading; if none is
present it directs you to run =org-chronicle-wikidata-import= first.

** Date coverage

The integration targets mostly-modern, precisely-dated subjects.  Dates
coarser than a year (decade or century Wikidata precision), BCE dates, and
dates before the year 1000 CE are not representable by the
=org-chronicle= date model and are dropped rather than approximated.
Affected fields are silently omitted from the proposed change set.

* Writing: scenes & continuity

Tie creative prose to the timeline and check it for continuity with the
historical record.  A *scene* is any heading carrying =:EVENT:=,
=:AFTER:= / =:BEFORE:=, a fictional own =:DATE:=, or an inline =chronicle:=
link.  Because a scene is just a property on a heading you already have, this
composes with org-novelist and binder layouts and stays invisible in the
exported manuscript.  (fountain-mode files are not Org, so scene markup does
not apply to them.)

#+begin_src org
,*** The siege begins
    :PROPERTIES:
    :EVENT: [[id:vicksburg-1863]]
    :END:
    Grant's guns opened at dawn.  [[chronicle:eliza][Mrs. Grant]] watched.
#+end_src

A scene may instead *define a fictional event* by carrying its own =:DATE:=
(and =:TRUTH: fictional=), optionally constrained relative to other events:

#+begin_src org
,*** A wager in the officers' tent
    :PROPERTIES:
    :DATE:   <1863-06-20>
    :TRUTH:  fictional
    :AFTER:  [[id:vicksburg-1863]]
    :BEFORE: [[id:appomattox-1865]]
    :END:
#+end_src

- =M-x org-chronicle-insert-reference= inserts an inline =chronicle:= link.
- =M-x org-chronicle-set-event= / =org-chronicle-add-constraint= set the
  =:EVENT:= / =:AFTER:= / =:BEFORE:= properties with completion.
- =M-x org-chronicle-lint-scenes= reports each scene's continuity findings and
  its *feasible window* — the range in which every reference and constraint is
  satisfied.  Floating (undated) scenes are surfaced with their window; an
  empty window means the references cannot co-exist at any date.
- =M-x org-chronicle-set-scene-date= (or =s= on a finding in the lint buffer)
  sets the scene's =:DATE:= to a value chosen from that window.

Constraints are evaluated against referents' *current* dates — there is no
propagation.  Pin scenes bounded by historical events first, then re-run the
lint as you place the rest.
