#+TITLE: org-chronicle schema

* Sources
  Events and entities are gathered from every =*.org= file found by
  recursively scanning =org-chronicle-root=, minus any path whose
  root-relative form (a leading =/= is prepended before matching) matches
  a regexp in =org-chronicle-exclude=, and minus any file that carries a
  =#+CHRONICLE: ignore= keyword.  Entities are no longer tied to a fixed
  file list; any file under the root may contain entity headings.

* Events (timeline file)
  One heading per event; identified by a non-empty =DATE= property.
  | Property  | Meaning                                            |
  |-----------+----------------------------------------------------|
  | ID        | org-id, stable link target                         |
  | TRUTH     | historical \vert fictionalized \vert fictional     |
  | DATE      | start, Org timestamp                               |
  | DATE-END  | optional end (durations)                           |
  | PEOPLE    | semicolon-separated participant names              |
  | LOCATION  | place name                                         |
  | TOPICS    | semicolon-separated topic names                    |
  | SOURCES   | semicolon-separated id links and/or free text      |

  =TRUTH= is mirrored to a tag of the same name by =org-chronicle-normalize=.

* Scenes (prose continuity)
  A scene is any heading in a prose file that ties narrative to the
  timeline.  A heading becomes a scene when it carries any of: =EVENT=,
  =AFTER=, =BEFORE=, a fictional own =DATE= (with =TRUTH: fictional=), or an
  inline =chronicle:= link in its subtree.  org-chronicle never creates
  scene headings; tag whatever heading already bounds the scene.
  | Property | Meaning                                                |
  |----------+--------------------------------------------------------|
  | EVENT    | id link(s) to the event(s) the scene depicts (anchor)  |
  | AFTER    | id link(s); scene date must fall on/after the referent |
  | BEFORE   | id link(s); scene date must fall on/before the referent|

  Inline references use a dedicated link type,
  =[[chronicle:ID][name as written]]=, where the description is the name used
  in the prose (consumed by the name-validity check) and the target is an
  event or entity id.  On export the markup is replaced by its description.

  A scene's *temporal anchor* is its own =DATE= if present, else its =EVENT=
  event dates, else it is *floating*.  =M-x org-chronicle-lint-scenes= checks
  each scene's references against that anchor (existence spans, name validity
  at date, dangling references) and reports a *feasible window* — the date
  range satisfying every reference and constraint.  =M-x
  org-chronicle-set-scene-date= (also =s= in the lint buffer) sets the
  scene's =DATE= to a value from that window.

* Entities
  One heading per entity; identified by a =KIND= property.  Entity
  headings may appear in any =*.org= file under =org-chronicle-root=.
  | Property   | Meaning                                    |
  |------------+--------------------------------------------|
  | KIND       | person \vert place \vert group \vert topic |
  | ALIASES    | semicolon-separated name variants          |
  | MEMBER-OF  | group ids (people)                         |
  | PART-OF    | parent place id (places)                   |
  | PARENTS    | parent person ids                          |
  | SPOUSE     | spouse person ids                          |
  | BIRTHPLACE | place id                                   |
  | DEATHPLACE | place id                                   |

  Topics are thematic threads (e.g. crime, shipping, census).  A topic
  entity carries only =ALIASES= and an optional =DESCRIPTION=; it has no
  existence span and is filed in =org-chronicle-topics-file=.  Create
  topics with =M-x org-chronicle-add-topic=.

** Existence spans (by kind)
   Applies to =person=, =place=, and =group= only; topics have no span.
   | Kind   | Start property | End property |
   |--------+----------------+-------------|
   | person | BORN           | DIED        |
   | place  | BUILT          | RAZED       |
   | group  | FOUNDED        | DISBANDED   |

* Life events
  Birth, death, marriage, and name-change are ordinary events carrying two
  extra properties.  A person's existence span, places, and spouse are
  derived from them, falling back to the entity properties below.
  | Property   | Meaning                                            |
  |------------+----------------------------------------------------|
  | LIFE-EVENT | birth \vert death \vert marriage \vert name-change |
  | SUBJECT    | principal name(s); two for marriage                |
  | NEW-NAME   | the adopted name (name-change only)                |
  LIFE-EVENT is mirrored to a tag (hyphens become underscores, so
  =name-change= tags as =name_change=).  A name-change accrues its NEW-NAME
  into the subject entity's ALIASES.  Capture with =M-x
  org-chronicle-add-life-event=.  Glyphs in the view are configurable via
  =org-chronicle-life-event-glyphs= (default: birth ⊕, death ⊗, marriage
  ⚭, name-change ↦).

* Timeline view
  =M-x org-chronicle-timeline=, or a dynamic block:
  : #+BEGIN: chronicle :people ("Grant" "Lincoln") :from "1862" :until "1865" :mode :collapse
  : #+END:
  Parameters: =:people= =:locations= =:topics= (lane names), =:truth= (subset),
  =:from= =:until= (date strings), =:mode= (=:collapse= or =:expand=).
  Topic columns can show a per-topic glyph and face via
  =org-chronicle-topic-glyphs= and =org-chronicle-topic-faces=.
