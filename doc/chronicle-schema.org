#+TITLE: org-chronicle schema

* Sources
  Events and entities are gathered from every =*.org= file found by
  recursively scanning =org-chronicle-root=, minus any path whose
  root-relative form (a leading =/= is prepended before matching) matches
  a regexp in =org-chronicle-exclude=, and minus any file that carries a
  =#+CHRONICLE: ignore= keyword.  Entities are no longer tied to a fixed
  file list; any file under the root may contain entity headings.

* Events
  One heading per event; identified by a non-empty =DATE= property.  New
  events are filed to =org-chronicle-timeline-file= by default, but events
  are read from every =*.org= file under the root.
  | Property  | Meaning                                            |
  |-----------+----------------------------------------------------|
  | ID        | org-id, stable link target                         |
  | TRUTH     | historical \vert fictionalized \vert fictional     |
  | DATE      | start, Org timestamp                               |
  | DATE-END  | optional end (durations)                           |
  | PEOPLE    | semicolon-separated names of every participant     |
  | LOCATION  | place name                                         |
  | TOPICS    | semicolon-separated topic names                    |
  | SOURCES   | semicolon-separated id links and/or free text      |

  =PEOPLE= is the event's full cast — everyone taking part.  =PEOPLE=,
  =LOCATION=, and =TOPICS= place the event in the matching timeline lanes,
  and =PEOPLE= / =LOCATION= are checked by the anachronism lint (each must be
  extant at the event's =DATE=).  =TRUTH= is mirrored to a tag of the same
  name by =org-chronicle-normalize=.  A /life event/ additionally carries
  =LIFE-EVENT= and =SUBJECT= (see *Life events* for how =SUBJECT= relates to
  =PEOPLE=).

* Scenes (prose continuity)
  A scene is any heading in a prose file that ties narrative to the
  timeline.  A heading becomes a scene when it carries any of: =EVENT=,
  =AFTER=, =BEFORE=, =EARLIEST=, =LATEST=, a fictional own =DATE= (with
  =TRUTH: fictional=), or an inline =chronicle:= link in its subtree.
  org-chronicle never creates scene headings; tag whatever heading already
  bounds the scene.
  | Property | Meaning                                                |
  |----------+--------------------------------------------------------|
  | EVENT    | id link(s) to the event(s) the scene depicts (anchor)  |
  | AFTER    | id link(s); scene date must fall on/after the referent |
  | BEFORE   | id link(s); scene date must fall on/before the referent|
  | EARLIEST | inclusive absolute lower bound the author sets directly |
  | LATEST   | inclusive absolute upper bound the author sets directly |

  =EARLIEST= and =LATEST= are partial dates (year, year-month, or
  year-month-day) set directly by the author — not derived from events.
  Either or both may be present; the heading remains floating (no =DATE=
  required) until the solver assigns one.  Precision is expanded to the
  widest matching day: =EARLIEST: 1850= means on/after 1850-01-01, and
  =LATEST: 1855= means on/before 1855-12-31.

  Inline references use a dedicated link type,
  =[[chronicle:ID][name as written]]=, where the description is the name used
  in the prose (consumed by the name-validity check) and the target is an
  event or entity id.  On export the markup is replaced by its description.

  A scene's *temporal anchor* is its own =DATE= if present, else its =EVENT=
  event dates, else it is *floating*.  =M-x org-chronicle-lint-scenes= checks
  each scene's references against that anchor (existence spans, name validity
  at date, dangling references) and reports a *feasible window* — the date
  range satisfying every reference and constraint.  =M-x
  org-chronicle-set-scene-date= (also =s= in the lint buffer) sets the
  scene's =DATE= to a value from that window.

  Scenes carrying an =:ID:= property are *reference targets*: they appear in
  the completion list for =chronicle:= links and for =AFTER= / =BEFORE=
  constraints, just like events and entities.  A =chronicle:= link to a scene
  is navigational only — it does not impose any temporal bound on the scene
  that contains the link.  =M-x org-chronicle-add-constraint= mints an =:ID:=
  on a target scene heading that lacks one (via =org-id-get-create=), so the
  resulting =[[id:…]]= link resolves immediately.

* Entities
  One heading per entity; identified by a =KIND= property.  Entity
  headings may appear in any =*.org= file under =org-chronicle-root=.
  | Property   | Meaning                                    |
  |------------+--------------------------------------------|
  | KIND       | person \vert place \vert group \vert topic |
  | ALIASES    | semicolon-separated name variants          |
  | MEMBER-OF  | group ids (people)                         |
  | PART-OF    | parent place id (places)                   |
  | PARENTS    | parent person ids                          |
  | SPOUSE     | spouse person ids                          |
  | BIRTHPLACE | place id                                   |
  | DEATHPLACE | place id                                   |

  Topics are thematic threads (e.g. crime, shipping, census).  A topic
  entity carries only =ALIASES= and an optional =DESCRIPTION=; it has no
  existence span and is filed in =org-chronicle-topics-file=.  Create
  topics with =M-x org-chronicle-add-topic=.

** Existence spans (by kind)
   Applies to =person=, =place=, and =group= only; topics have no span.
   | Kind   | Start property | End property |
   |--------+----------------+-------------|
   | person | BORN           | DIED        |
   | place  | BUILT          | RAZED       |
   | group  | FOUNDED        | DISBANDED   |

* Life events
  A life event is an ordinary event (it has a =DATE=) that additionally
  carries =LIFE-EVENT= and =SUBJECT=.  Births, deaths, marriages, and
  name-changes are recorded this way.
  | Property   | Meaning                                                   |
  |------------+-----------------------------------------------------------|
  | LIFE-EVENT | birth \vert death \vert marriage \vert name-change        |
  | SUBJECT    | the principal(s) the event is /about/; two for a marriage |
  | NEW-NAME   | the adopted name (name-change only)                       |

  *Subject vs. people.*  =SUBJECT= names the person(s) the event is
  /about/ — whose birth, death, marriage, or name-change it records (a
  marriage has two).  =PEOPLE= (the ordinary event property) names
  /everyone/ taking part and, by convention, includes the subject: a
  birth's =PEOPLE= is the subject plus the parents; a marriage's =PEOPLE= is
  its two subjects.  So the subjects are a subset of the people, with
  =SUBJECT= marking which of the cast the event principally concerns.

  A person's existence span, birthplace/deathplace, and spouse are /derived/
  from the life events whose =SUBJECT= is that person, falling back to the
  entity's own =BORN= / =DIED= / =BIRTHPLACE= / =DEATHPLACE= / =SPOUSE=.  In the
  timeline an event joins a person's lane when that person is in its
  =PEOPLE= /or/ is one of its =SUBJECT= s, so a person's own life events
  appear in their lane even if =PEOPLE= was left empty.

  =LIFE-EVENT= is mirrored to a tag (hyphens become underscores, so
  =name-change= tags as =name_change=).  A name-change accrues its NEW-NAME
  into the subject entity's =ALIASES=.  Capture with =M-x
  org-chronicle-add-life-event=, which fills =PEOPLE= from the subject and
  any parents; the importers do the same.  Glyphs in the view are
  configurable via =org-chronicle-life-event-glyphs= (default: birth ⊕,
  death ⊗, marriage ⚭, name-change ↦).

* Provenance and import properties
  Written by the import commands (=org-chronicle-import= and the bulk
  importers); tool-managed rather than hand-authored.  They sit on events
  and/or entities alongside the schema properties above.
  | Property   | On            | Meaning                                          |
  |------------+---------------+--------------------------------------------------|
  | WIKIDATA   | event, entity | the item's Wikidata QID (a source key property)  |
  | FACTGRID   | event, entity | the item's FactGrid id (a source key property)   |
  | WIKIPEDIA  | event, entity | a reference link emitted by the source           |
  | IMPORT-KEY | event         | source-independent idempotency key for re-import |

  The source key property is named per source (the source's =:key-property=),
  so a heading may carry both =WIKIDATA= and =FACTGRID= when imported from
  each.  =SOURCES= (above) is also written by import.  =IMPORT-KEY= lets a
  re-import update the existing heading in place rather than duplicating it.

* Timeline view
  =M-x org-chronicle-timeline=, or a dynamic block:
  : #+BEGIN: chronicle :people ("Grant" "Lincoln") :from "1862" :until "1865" :mode :collapse
  : #+END:
  Parameters: =:people= =:locations= =:topics= (lane names), =:truth= (subset),
  =:from= =:until= (date strings), =:mode= (=:collapse= or =:expand=).
  Topic columns can show a per-topic glyph and face via
  =org-chronicle-topic-glyphs= and =org-chronicle-topic-faces=.
